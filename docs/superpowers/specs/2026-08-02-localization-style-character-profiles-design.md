# Unity Mono 汉化风格指南与角色档案设计

## 目标

为 `localizing-unity-mono-games` 增加可复用、可脚手架化、可验证的翻译风格指南与角色档案。开始大批量翻译前，项目必须先根据完整可用原文建立全局翻译契约和按角色划分的证据档案，再由人工审核。

通用 skill 不携带任何特定游戏的职业或题材政策。心理咨询、警务及其它领域表达只能由具体项目写入其自己的领域规范；模板只提供中性的“项目领域政策”插槽。

## 方案选择

采用“两个项目模板 + Phase 3 证据流程 + 结构测试”的方案：

1. `localization/translation-guide.md` 保存整个游戏共享的翻译风格契约。
2. `localization/characters/CHARACTER.md.example` 定义单角色档案结构；识别出真实角色后，为每个角色建立独立文件。
3. `references/paratranz-and-profiles.md` 规定如何从完整原文证据生成、审核和使用这些文件。
4. `scaffold_project.py` 自动复制模板；`validate_project.py` 检查必要结构存在。
5. `test_skill_scripts.py` 锁定模板字段、脚手架、验证器及“不得夹带具体游戏领域规则”的边界。

不采用仅在参考文档中增加几段提醒的方案，因为现状已经证明软性要求会产生只有四行的角色档案。也不采用一个包含所有角色的单文件，因为它不利于按说话人加载、审核和更新。

## 全局翻译风格指南

模板至少包含以下部分：

- 目标语言、地区与读者；
- 全局语域、叙事距离和自然化程度；
- 人称代词、敬语、称谓与关系变化；
- 俚语、粗口、冒犯性语言、口语缩略和网络表达政策；
- 幽默、讽刺、双关和文化指涉的处理原则；
- 标点、省略号、大小写强调、数字、日期和单位；
- 换行、字符长度、UI、对白、选项、系统文本的分别约束；
- 占位符、富文本标签、转义和不可翻译内容；
- 专名与术语表优先级；
- 项目自定义领域政策索引；
- 不确定项的升级与人工裁决规则；
- few-shot 正例和反例。

Few-shot 条目必须包含原文、推荐译文、适用场景、理由和来源 key。反例还要说明错误原因。示例必须来自该项目已审核文本，模板本身不预填某一游戏的具体译句。

“项目自定义领域政策”只记录项目自己选择的文件或章节，例如 `localization/domains/<domain>.md`；通用模板不列举心理咨询、警务或任何其它具体职业领域，也不提供相关术语。

## 角色档案

每个真实角色一个 Markdown 文件，包含以下契约。

### 身份与覆盖范围

- canonical ID、显示名、别名和角色类型；
- 出现的路线、章节和剧情阶段；
- 已分析原文数量、覆盖范围及尚未覆盖的来源；
- 主要关系以及各关系中的称谓。

### 整体人物画像

- `Observed`：原文直接支持的身份、行为和经历；
- `Inferred`：由多条原文归纳的性格、价值倾向、动机、恐惧、欲望、矛盾、应对方式和决策模式；
- `Unknown/Conflicting`：证据不足或不同路线冲突的结论；
- 剧情阶段变化和人物弧线。

每项推断必须附 `high`、`medium` 或 `low` 置信度以及至少一个来源 key。不得把单句印象写成确定事实。对白极少的背景角色允许只建立最小档案，不得为了填满模板虚构完整人格。

### 语言指纹

- 常用词、口头禅和重复短语，尽量记录出现次数与来源 key；
- 句长、句法复杂度、停顿、犹豫词、重复、强调和省略习惯；
- 正式度、礼貌度、称谓、俚语、粗口与委婉表达；
- 常见言语行为，例如回避、质问、安慰、命令、自我修正；
- 情绪、关系和剧情阶段变化时的说话差异。

### 翻译契约与示例

- 中文语域、句长、节奏、人称和称谓；
- 推荐用词、允许变体和禁用表达；
- 必须保留的个性特征及允许自然化的部分；
- 至少少量经过人工审核的原文—译文 few-shot；
- 不符合角色的反例及原因。

## 证据生成流程

1. 从 `resources/work/entries.jsonl` 或经验证的提取 CSV 按 speaker/角色稳定 ID 汇总全部可用原文。
2. 计算可复现的表层统计：文本数量、路线覆盖、重复词语、常用短语、句长和标点/停顿特征。
3. 结合故事流和关系证据写出 `Observed`、`Inferred`、`Unknown/Conflicting`，为每条结论保留 key 和置信度。
4. 从已经人工审核的译文选择 few-shot；没有审核译文时将示例标为待审核，不把机器初译当成风格基准。
5. 人工审阅全局指南和主要角色档案后，才开始全量对白翻译。
6. 翻译时加载全局指南、术语表以及当前说话人的档案；跨角色对话同时参考关系和称谓规则。
7. 新路线或新证据推翻旧结论时更新档案，保留冲突说明，不静默覆盖。

自动统计只能提供证据，不能自动决定人物性格。常用语句必须基于真实出现频率或人工确认，不能由模型仿写后再当作证据。

## 脚手架与兼容性

新增模板：

- `assets/project-template/localization/translation-guide.md`
- `assets/project-template/localization/characters/CHARACTER.md.example`

新项目通过现有模板复制机制获得两者。对于已有项目，skill 指示先保留现有内容，再按缺失章节进行 retrofit，不覆盖人工编辑过的指南或角色档案。

`validate_project.py` 只做结构门禁：要求翻译指南和角色目录存在。新脚手架必须包含角色模板，但已有项目只要已经存在真实角色档案，就不因缺少示例文件而失效。内容是否已经针对游戏填写完整属于 Phase 3 人工门禁，不能仅凭关键词数量自动判定。

## 验证

自动测试必须覆盖：

- 新脚手架包含风格指南和角色模板；
- 新项目仍能通过 `validate_project.py`；
- 删除风格指南或角色目录会导致验证失败；新脚手架缺少角色模板时由脚手架测试失败；
- 风格指南包含语域、称谓/敬语、俚语/粗口、格式、领域政策插槽和 few-shot 契约；
- 角色模板包含整体画像、Observed/Inferred/Unknown、动机与矛盾、关系、剧情阶段、语言指纹、常用语句、置信度、来源 key、正反例；
- 两个新模板和新增的通用指导不包含心理咨询、警务或任何具体游戏领域术语；
- 现有项目 retrofit 不覆盖已有文件。

前向测试使用一个非 Psycholog、非现代职业题材的 Unity Mono 游戏场景。新 Codex 实例应先从完整角色语料形成证据档案，区分事实与推断，记录高频语句和 key，并在人工审核后才进行全量翻译；不得引入心理咨询或警务术语。

## 非目标

- 本次不重写 Psycholog 现有 `translation-guide.md` 或角色档案；它们是后续项目级 retrofit。
- 不把人物推断视为剧情事实。
- 不用模型生成的口头禅反向证明角色有该语言习惯。
- 不强迫只有一两句台词的背景角色拥有虚构的完整人格。
- 不在通用 skill 中固化任何具体游戏、职业或题材的领域词汇。
