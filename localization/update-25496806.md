# Steam build 25496806 compatibility repair

PsychologHan v0.2 (assembly version 0.2.0) targets Psycholog's Unity 6000.4.4f1 Mono x64 build.
The supported assembly hashes are recorded in `project-profile.json` and
included in the generated package manifest.

## Cause

BepInEx still loaded the old plugin and all 5,512 translations. The failure
occurred when a UI refresh tried to apply a font mapping. Unity's `Player.log`
reported `MissingFieldException: TMPro.TMP_Asset.material`; this exception did
not appear in the old BepInEx log.

ILSpy and Mono.Cecil inspection identified two binary API changes:

- `TMP_Asset.material` changed from a public field to a property. The installed
  DLL used `ldfld`; rebuilding against the current game emits `get_material()`.
- `Scene.get_handle()` no longer has the old `Int32` return signature. This
  also broke the diagnostic F8 scene scanner in the old binary.

The C# expressions still compile, so source-only tests cannot catch this
failure. The repair rebuilds the plugin against the supported game's managed
assemblies and adds a binary member-reference check.

The decompiled story comparison also found seven punctuation encoding changes,
with no added or removed dialogue/choice identities (2,478 dialogue identities
and 1,333 choice identities). `TranslationManager.RuntimeOriginalsMatch`
accepts only those verified substitutions at their category/node keys:

| Category / identity | Source change |
| --- | --- |
| dialogue: 88106/ME, 88110/ME, 88111/ME | U+2019 to U+009D |
| dialogue: 26616/RAYMOND | U+2019 to `?` |
| dialogue: 26581/RAYMOND | U+2026 to `?` |
| choice: 26585/26585, 26600/26602 | U+2019 to `?` |

The full source must still match after the specific substitution. Other
categories/nodes, changed prose, ambiguous aliases and missing translations
retain the original fallback behavior. Approved CSVs remain unchanged.

## Reproduce and verify

Configure `Directory.Build.props` for the installed build, then run:

```powershell
dotnet build PsychologHan.csproj -c Release --no-restore
python -m unittest discover -s tests -v

# Set these paths to the target install, using its actual Mono.Cecil.dll.
pwsh -NoProfile -File scripts/check_runtime_compatibility.ps1 `
    -PluginPath bin/Release/netstandard2.1/PsychologHan.dll `
    -ManagedDirectory "$gamePath/Psycholog_Data/Managed" `
    -CecilPath "$gamePath/BepInEx/core/Mono.Cecil.dll"

python scripts/validate_localization.py --project-root . `
    --translations resources/work/approved-translations `
    --profile localization/project-profile.json --dist dist
```

The binary checker returns a nonzero exit code for the old plugin: 96 member
references checked, two missing. The repaired DLL resolves all 97 references.
It checks metadata only; Harmony targets, rendering and gameplay need runtime
verification too. Its regression tests generate temporary assemblies and do
not require an installed game. Tests use PowerShell 7 and a cached Mono.Cecil
package, or `PSYCHOLOGHAN_CECIL_PATH`. The text regression test compiles and runs
the actual C# translation manager with temporary CSVs.

## Deceased client records

The reported save reproduces both issues before the client-status repair:
the client page shows one deceased stamp, and both Vera comments read
`Treatment is cancelled due to client's death.` The ending page correctly
shows three deaths. The save has `veraDied`, `ashleyDied`, `deborahDied` set,
but only `notifiedDeathVera` is set (`timeCode=2240`, `currentSitItem=45300`).

These are separate causes:

- The English notice predates the update. ILSpy emits chained assignments,
  e.g. `treatmentCommentVera = (trustCommentVera = "...")`, which the extractor
  discarded. It now extracts both targets for all five clients. Ten new
  `client_info` rows use **来访者已去世，治疗已终止。** Existing 50 reviewed rows
  are preserved. `apply_client_info_translation.py` accepts these additions
  without shifting its ordinary translations or overwriting reviewed edits.
- The ending reads death flags; the client page reads notification flags.
  The old game never sets Ashley/Deborah notifications. The new game adds
  them at dialogue 37080/42115, but `ApplySaveCompatibility()` migrates only
  `killedX` to `xDied`; it does not replay past notifications for old saves.

`ClientDeathStatus` applies a display-only correction. Ashley's death is
decided at 21160 before the police disclosure; the legacy fallback waits for
the following map at `timeCode >= 2130`. Deborah's death is set only at the
police disclosure itself, 42115, so that flag is sufficient. Other clients
retain the notification rule. The patch never changes story flags, scores,
achievements, or save files. Confirmed deaths show the translated cancellation
message even if the game's stored comments have not yet been recomputed.

The red `DECEASED` stamp is a sprite asset, separate from the comment text;
this repair changes when its existing image is shown, not the image artwork.

Regression coverage includes chained assignment extraction, translation
preservation, notification timing, surviving routes, legacy fields and
unchanged state. All 111 tests, Release build, localization validation and
109 compiled game/Unity member references pass. Runtime evidence is kept in
the ignored `artifacts/update-20261023/` directory: `death-before-fix.log`
records one stamp and the English notice; `death-after-fix.log` records the
checks against the repaired plugin. The temporary component does not invoke
story-choice callbacks, the ending achievement logic, or save-writing APIs.
The repaired run displays all three stamps, translates both comments for
each dead client, preserves the original save flags, and hides Ashley's death
before disclosure. Fresh notification fixtures for all five clients also pass.
Unity's `death-after-fix-unity.log` ends with `PASS failures=0`; BepInEx's disk listener
buffered that last message, so the deployment harness now accepts the final
marker from either log. Save-file hashes are unchanged and the temporary
probe DLL/config were removed. Visual layout still needs in-game inspection.

## Ending exit label remains visible

The ending's `GameResult/ReturnToTitleButton/Text (TMP)` was already translated.
Its parent button uses an `Image` plus `Mask` with a transparent normal color
(alpha 0) and a nearly transparent hover color (alpha 1/255). The text's mask
therefore only passes pixels while hovering. This is serialized UI behavior,
not a missing translation or a new mouse-input failure.

The existing approved hierarchy locator for TMP PathID 34132 now sets only
that label's `maskable` property to false. Button colors, the mask component,
raycast targets, and the original `ToMainAfterFinishing` click controller are
untouched. The same-named button in `DifficultySetting` retains its behavior.

Verification uses a clone of the actual button in a separate camera canvas,
with gameplay controllers disabled. It never activates the ending achievement
logic, invokes story choices, or writes saves. Restoring the old mask setting
reproduced 0 visible text pixels in normal state and 3,203 on hover. With the
repair, normal, hover, pointer-exit and reopened states render the same 3,203
pixels. A pointer-click event still reaches the fixture's button listener.
The captured Chinese text was also visually inspected.

All 111 Python tests, the Release build, localization packaging, and all 110
compiled game/Unity member references passed. The real game-process probe
reported `PASS failures=0`, and save hashes remained unchanged. The tested
binary was installed in the existing flat plugin layout. Captures are stored under
`artifacts/update-20261023/ending-button-*.png`; the previous binary is in
`artifacts/update-20261023/backup-20261023-235851/`.
